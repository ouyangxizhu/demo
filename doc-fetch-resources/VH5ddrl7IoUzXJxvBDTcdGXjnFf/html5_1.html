Store 不是一组并列类，而是契约、适配与后端三层
纵轴＝从调用语义到实际介质 · 分类依据＝抽象职责，而非类名相似度｜截至 2026-10-16
契约层 L3BaseStore[K,V] 定义最小批量接口屏蔽后端差异，只承诺键值批处理与键遍历
批量读取mget / amget；按输入顺序返回，缺失位为 None
批量写删mset、mdelete 及异步对应方法
键遍历yield_keys / ayield_keys；仅有可选 prefix
ByteStore 是类型别名BaseStore[str, bytes]，不是独立后端类
langchain-core
适配层 L2EncoderBackedStore 转换业务键值自身实现 BaseStore，同时组合一个底层 Store；不提供持久性
键编码key_encoder 把业务键 K 映射为稳定字符串
值序列化value_serializer 把 V 转成底层可存格式
值反序列化value_deserializer 恢复业务对象；None 原样保留
组合而非介质持久性、原子性与并发能力均由所包装后端决定
langchain-classic
后端层 L1可实例化实现承担实际存取同一批量契约下，数据形态与生命周期明显不同
InMemoryStoredict[str, Any]；进程内、易失，适合对象与测试
langchain-core
InMemoryByteStoredict[str, bytes]；内存字节后端，不跨进程
langchain-core
LocalFileStore字符串键映射本地文件；单机字节持久化
langchain-classic
外部适配实现MongoDB、Redis、Astra DB 等可承载持久化与共享
integration
